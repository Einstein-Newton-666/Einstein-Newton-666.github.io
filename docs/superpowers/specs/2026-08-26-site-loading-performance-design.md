# 网站加载性能优化设计

## 目标

在不降低当前首页与内页正式背景画质、不修改 Redefine 主题源码的前提下，降低首次访问的等待时间，并优先采用 Redefine 2.9 官方支持的配置方式。

## 已确认瓶颈

- 首页冷加载约 62 个请求、1.54 MB，其中字体约 829 KB、图片约 475 KB。
- 主题 CSS、JavaScript 与 Font Awesome 当前全部由 GitHub Pages 提供，缓存时间约 10 分钟。
- Redefine 官方演示站通过 `npmmirror` 分发版本固定的主题资源，并为该域名添加预连接。
- 首页场景切换器直接使用三张 1920px 图片作为缩略图，导致三个完整场景在首屏全部下载。
- 头像源文件为 900x900、约 123 KB，而页面展示尺寸远小于源图。
- 搜索索引在每个页面首屏预加载；当前体积较小，但会随文章数量持续增长。

## 方案选择

### 采用方案：官方 CDN 加轻量展示资源

1. 在 `_config.redefine.yml` 启用 Redefine 官方 `cdn` 配置，服务商使用 `npmmirror`。
2. 保留所有现有 1920px 与 4K 正式图片，新增三张约 320x180 的首页场景缩略图。
3. 场景按钮只加载缩略图；当前场景继续加载正式图片，其他正式图片在用户点击后再加载。
4. 新增 320x320 的头像展示版，保留 900x900 原图作为可恢复的高质量源文件。
5. 将搜索索引改为打开搜索框时按需加载。
6. 保留 `global.single_page: true`、文章图片懒加载、现有 4K 选择规则和页面视觉效果。

### 未采用方案

- 仅压低所有背景图质量：会直接损害此前确认的清晰度要求。
- 关闭 Swup 单页切换：能减少少量首屏脚本，但会降低站内后续导航体验，也偏离官方演示站方案。
- 将自定义图片全部迁移到第三方图床：运维复杂度和外部依赖明显增加，当前阶段收益不足。

## 验收标准

- `npm test` 全部通过，生成的页面仍保留首页、分类、标签、归档、文章、搜索、RSS 和明暗模式。
- 生成 HTML 中主题静态资源指向 `registry.npmmirror.com/hexo-theme-redefine/2.9.0/`，自定义 CSS、脚本和图片仍使用本站路径。
- 搜索页面初始化时不请求 `search.xml`，打开搜索框后能够正常请求并使用索引。
- 三张场景缩略图均为 WebP、最大边不超过 320px、单张不超过 30 KB。
- 头像展示版为 320x320 WebP，不超过 50 KB；页面不再首屏下载 900x900 原头像。
- 首屏只下载当前正式场景图，不下载另外两张正式场景图；点击对应按钮后能够正常切换并加载完整图片。
- 在 1440x1000 和 390x844 下检查首页及内页，无图片损坏、布局重叠、控制台错误或导航回归。

## 回退策略

CDN 可通过单个配置开关关闭；缩略图和头像均为新增文件，原始图片不删除。若外部 CDN 出现问题，可恢复本地主题资源加载而不影响文章和自定义视觉资源。
